# crackedpdfs-payloads

Assembles the prompt-injection payload pool for CrackedPDFs benchmark v2: a licensed, id-tagged,
near-duplicate-clustered set of injection messages drawn from the v1 hand-written library and six
public datasets and repositories.

`prompt-injection` `benchmark` `dataset` `provenance` `minhash` `near-duplicates`

## Why this exists

Benchmark v1 embedded 104 hand-written messages, 13 per message type, and every one of them
appeared in every split. Detectors trained on v1 could memorise the payload text instead of
learning what hidden-text injection looks like. v2 needs a pool that is large enough to hold out,
and whose paraphrase families are known in advance, so that a split can withhold entire clusters
rather than individual strings.

This package produces two artefacts:

| File | Contents |
| --- | --- |
| `data/payloads.jsonl` | One message per line with a stable id, provenance, language, message type, cluster id, and nearest-v1 similarity |
| `data/sources.json` | Per-source provenance (URL, retrieval date, revision, licence evidence, raw and kept counts, skip reasons) and the pool summary |

## Sources

Every source is downloaded programmatically and pinned to the revision observed at build time.
Licence confirmation is mandatory: a Hugging Face dataset is accepted only when its dataset card
declares the expected permissive licence, and a GitHub repository only when its `LICENSE` file is
the MIT licence. A source that fails the check is recorded in `sources.json` with `skipped: true`
and a reason, and contributes no messages.

| Source name | Origin | Licence | Selection |
| --- | --- | --- | --- |
| `crackedpdfs-v1` | `src/lib/prompt-injection-message-library.ts` in this repository | MIT | All 104 messages, parsed from the TypeScript literal with a regular expression; author-assigned types kept |
| `deepset-prompt-injections` | [deepset/prompt-injections](https://huggingface.co/datasets/deepset/prompt-injections) | Apache-2.0 (card header; the `dataset_info` block also lists CC-BY-4.0, noted in the manifest) | Rows with `label == 1` from train and test; German rows kept with `language` set |
| `spml-chatbot-prompt-injection` | [reshabhs/SPML_Chatbot_Prompt_Injection](https://huggingface.co/datasets/reshabhs/SPML_Chatbot_Prompt_Injection) | MIT | `User Prompt` for rows with `Prompt injection == 1`; `Degree` and upstream `Source` kept in `source_record` |
| `lakera-gandalf-ignore-instructions` | [Lakera/gandalf_ignore_instructions](https://huggingface.co/datasets/Lakera/gandalf_ignore_instructions) | MIT | All rows from train, validation, and test |
| `jackhhao-jailbreak-classification` | [jackhhao/jailbreak-classification](https://huggingface.co/datasets/jackhhao/jailbreak-classification) | Apache-2.0 | Rows with `type == "jailbreak"` from train and test |
| `agentdojo-injection-tasks` | [ethz-spylab/agentdojo](https://github.com/ethz-spylab/agentdojo) | MIT | Every `GOAL` class attribute in `src/agentdojo/default_suites/*/*/injection_tasks.py`; f-string constants (attacker IBANs, emails, links) are resolved statically |
| `open-prompt-injection` | [liu00222/Open-Prompt-Injection](https://github.com/liu00222/Open-Prompt-Injection) | MIT | Injected instructions in `data/system_prompts/*_inject*.txt` plus the compromise task, composed through the attacker templates (naive, ignore, fake completion, combined) |

Notes on Open-Prompt-Injection: the upstream attackers append a dataset-specific injected sample to
each instruction; that sample is omitted, so the pool holds the attacker templates themselves. The
escape-character attack differs from the naive attack only by a leading newline, which whitespace
normalisation removes, so it is folded into the naive template. One upstream demonstration file is
excluded because its example contains a racial slur; the exclusion is listed in the manifest notes.

## Processing

1. Normalise: NFC, collapse every whitespace run to one space, trim, strip matching surrounding
   quotes repeatedly (straight, backtick, typographic, and guillemets).
2. Filter: drop messages shorter than 20 or longer than 1,200 characters.
3. Deduplicate: exact, case-insensitive match on the normalised text. Sources are processed in the
   order of the table above, so the v1 copy of a text wins and keeps its author-assigned type.
4. Type: apply the keyword rules below. External messages get `message_type_source: "rule"`;
   v1 messages keep their original type with `message_type_source: "author"`.
5. Id: `pl-` plus the first 12 hex digits of SHA-256 over the normalised text.
6. Cluster: MinHash with 128 permutations over lowercase character 5-gram shingles, indexed with
   LSH at a 0.7 Jaccard threshold; candidate pairs are joined with union-find and each connected
   component becomes one cluster, `pc-` plus a zero-padded index assigned in id order.
7. v1 proximity: exact Jaccard of the shingle set against every v1 message, maximum stored in
   `nearest_v1_jaccard`. For v1 messages themselves the comparison excludes the message itself,
   so the value is the nearest distinct v1 neighbour.

## Message-type rules

Each type owns a list of case-insensitive regular expressions. A message receives the type with the
most matching expressions; ties resolve to the type listed first. A message that matches nothing is
`unclassified`. The complete expressions live in `src/crackedpdfs_payloads/normalize.py`
(`TYPE_RULES`); the table gives the cues in prose.

| Priority | Type | Cues |
| ---: | --- | --- |
| 1 | `summarization_steering` | summary, summarise; takeaway, headline, main point; hidden or embedded text framed against the document |
| 2 | `system_extraction` | system prompt or system message; repeat, reveal, print, dump, or disclose the instructions, rules, or prompt; verbatim or in full; hidden, confidential, or internal instructions |
| 3 | `data_exfiltration` | password, credentials, API key, token, secret, secret word; exfiltrate; send or post something to an address or URL; IBAN or account number; phishing; confidential or sensitive values |
| 4 | `agent_tool_manipulation` | use, call, invoke, or run a tool, function, browser, plugin, or shell; send, delete, schedule, modify, transfer, or book an email, event, transaction, payment, or file; tool calls; inspecting the environment or logs |
| 5 | `refusal_suppression` | do not refuse, warn, apologise, or hedge; without disclaimers or restrictions; unfiltered or uncensored; DAN, jailbreak, developer mode; free of restrictions; answer directly or anyway |
| 6 | `policy_framing` | policy, compliance, audit, exemption, authorised; red team, penetration test, security evaluation; for research, educational, or testing purposes; speaking as the developer, administrator, or creator; debug or maintenance mode |
| 7 | `instruction_override` | ignore, disregard, forget, or override previous, prior, or all instructions, rules, or context; new instructions; from now on; superseded, obsolete, revoked; German cues such as vergiss, ignoriere, vorherigen, ab jetzt |
| 8 | `task_hijack` | your real or actual task; instead of, rather than, but first; an imperative competing task at the start (write, answer, translate, classify, correct, repeat); respond with only or exactly; story, poem, joke |

Applied to the 104 author-labelled v1 messages, the rules reproduce the author type for 73 messages
(70 percent). The disagreements are mostly messages whose wording spans two types, for example a
task hijack phrased as a system-prompt extraction. The rule set is a transparent heuristic for
stratifying external messages, not a classifier; the `message_type_source` field keeps the two
provenances separate.

## Record schema

| Field | Meaning |
| --- | --- |
| `id` | `pl-` plus 12 hex digits of SHA-256 over `text` |
| `text` | Normalised payload text |
| `source` | Source name from the table above |
| `source_record` | Locator inside the source (split and row, suite and class, file and attacker template) |
| `license` | SPDX-style licence of the source |
| `url` | Source URL pinned to the revision that was read |
| `retrieved_at` | ISO date of the download |
| `language` | ISO 639-1 code from `langdetect` (seeded), or `und` when detection fails |
| `message_type` | One of the eight v1 types or `unclassified` |
| `message_type_source` | `author` for v1, `rule` for everything else |
| `cluster_id` | `pc-` plus zero-padded near-duplicate component index |
| `nearest_v1_jaccard` | Maximum exact Jaccard (5-gram shingles) to any v1 message other than itself |
| `char_length` | Length of `text` in characters |

## Usage

```bash
cd tools/crackedpdfs-payloads
uv venv --python 3.13 .venv
uv pip install -e ".[dev]"
crackedpdfs-payloads build --out data/       # downloads every source, writes data/, refreshes this README
crackedpdfs-payloads stats data/payloads.jsonl
pytest
ruff check .
```

`build` accepts `--v1-file` to point at a different copy of the v1 TypeScript library and
`--no-readme` to leave this file untouched. Set `GITHUB_TOKEN` to raise the GitHub API rate limit
when rebuilding often. Tests are fully offline.

## Holding out clusters

To build a v2 split that a detector cannot memorise, sample clusters rather than messages: group
`payloads.jsonl` by `cluster_id`, assign whole clusters to train, validation, and test, and treat
`nearest_v1_jaccard` as the leakage indicator for anything that resembles the v1 library. Messages
whose cluster contains a v1 message are the ones a v1-trained detector has effectively already seen.
